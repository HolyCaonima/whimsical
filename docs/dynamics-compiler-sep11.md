# 集合域编译与 GPU 执行优化（2026-09-11）

基线提交：`a8354ff`。本轮修改 Dynamics compiler 和 Field 的内部列式物化路径。用户 JavaScript DSL 输入、项目源码、自由度、关系公式、参数及求解策略默认值均保持不变；没有修改 RenderCore，没有新增或修改测试。

## 资料与架构取舍

- [Simit 2016](https://people.csail.mit.edu/jrk/simit.pdf) 利用图与张量索引的对应关系生成原位计算，并融合索引表达式。这里应用到不可变布局元数据：保持逻辑 ID 与公开字段地址，把表读取降成已验证的整数算术。Simit 本身的固定拓扑抽象不等于自动空间候选推导。
- [Ebb 2016，第 6 节](https://graphics.stanford.edu/~mdfisher/papers/ebb.pdf) 将关系模型与列式存储、仿射索引和隐藏分组索引分开。本轮统一变量和关系的元数据布局生成；也实际尝试了桶链表的连续分组，但额外 dispatch 抵消了查询收益，最终没有保留。
- [Newton v1.5.0 XPBD 源码](https://raw.githubusercontent.com/newton-physics/newton/v1.5.0/newton/_src/solvers/xpbd/solver_xpbd.py) 将空间候选与精确计算分离。Dynamics 已有从平方差不等式自动推导网格的实现，本轮进一步利用无向逻辑域消除重复邻格方向，并提高活动队列消费的并行度。Newton 的对象类别、专用方程、索引刷新周期没有迁入编译器。
- [Newton MPM 配置](https://newton-physics.github.io/newton/latest/api/_generated/newton.solvers.SolverImplicitMPM.html) 包含 voxel size、网格基函数与粒子网格传输方案。由这些离散语义判断，MPM 不能直接作为当前自由度和关系的等价实现；本轮没有将输入模型替换为 MPM。网格仍只是可证明的候选索引，不承担新的物理离散。

## 最终实现

### 统一不可变元数据布局

`MetadataRange<Width>`、`packMetadata()` 和 `metadataAccess()` 共用同一条编译路径处理变量的五列元数据和关系的九列元数据。至少 128 行的集合逐行验证 `base + row * stride`；符合条件时生成整数地址算术。小集合及非仿射集合保留紧凑表，相邻表范围合并，shader 使用平衡范围分支。

变量的状态、速度、度量基址、列跨度和结构只读标志因此不再要求每次访问读取五个元数据 word。数值逆度量、enabled、值、参数等仍从当前 GPU 字段读取，不能根据初始数值折叠。编译分析完成以后才压缩物理表，已有 Schedule、迁移、动态端点、patch 和回读仍使用原逻辑 ID。

候选 lowering 也改为直接读取所需的元数据 word，不再复制完整九列表。4,000 示例因此避免一次 288,792,000 bytes 的临时分配与复制。这是被删除的具体临时副本大小，不是实测进程峰值内存降幅；其他 O(P) 存储仍存在。

### 无向域的半邻域遍历

只有 `Upper/UpperDiagonal` 域、两侧成员数相同且特征列的底层仿射地址映射逐项相同时，才只查询一半邻格加本格。三维为 14 个方向，二维为 5 个，一维为 2 个。其他域继续使用原完整邻域。

跨格成员对由 cell 的字典序只枚举一次；本格沿用原 `i<j` 或 `i<=j`。在读取关系字段前统一为 `left=min(i,j), right=max(i,j)`，恢复原逻辑行及原左右端点。**这不要求用户关系对称**，也不会交换用户公式的参数或输入；对称的是候选特征的平方差和无向索引域。

浮点裕量、完整 cell 核对、精确 residual、旧非零乘子队列、当前 Jacobi 快照和越界完整遍历继续沿用原实现。失效时先走完整遍历，再返回，不套用半邻域剪枝。没有固定邻居数量上限，也没有减少迭代。

### 活动队列执行宽度与字段物化

每种数学类型的活动求解从最多 32 个工作组放宽到最多 128 个，每组仍为 128 个 lane，且不超过逻辑行数向上对齐后的宽度。更长队列继续循环消费，预算不限制关系数量。此值是通用后端启发式，不是按示例名称选择，也不是硬件自动调优器。

`Field::columnMajor()` 按不可变页组织物化：统一页直接连续填充，修改过的页按列转换，末页只处理实际行。Compiler 不再逐元素调用 `at()` 来重复做范围及页索引查询。公开字段的行主序输入、统一值、局部 patch 和快照共享语义不变。

计算阶段 dispatch 数保持 205/tick；收益来自减少索引与元数据访问、改善并行度，而非减少求解步骤。

## 对照与验证

RTX 3080，Release，Vulkan validation 开启，无界面 `dynamics_run --profile`。使用已有 `captures/compiler-perf/paired-dsl.js`，它保留项目原始数学定义及固定随机种子 12345：4,000 个可写三维自由度、8,022,000 条关系、Hybrid、4 子步 × 12 迭代、每 tick 1/30 秒，共 90 tick。回读 tick 1、90 的完整状态。

先强制重建基线：初始增量构建实际复用了旧的按类型拆分求解版本，和当前源码不符，该次样本已覆盖且未进入最终比较。最终以基线和优化版各自保存的可执行文件进行交替对照。没有锁 GPU 频率，运行间有明显波动，全部三轮均保留。

GPU 数字是 tick 46–90 的完整 Dynamics 提交时间戳均值，含提交内同步、传输及队列影响，不是整帧时间或纯算术时间。CPU 数字是 `X.compile` 前后时间，包含 model commit 和计划生成，不包含后续 GPU 程序创建。

## 剩余成本

CPU 仍逐逻辑关系展开和分析，参数、乘子与最坏容量双活动队列仍为 dense。此次没有实现 O(N) 编译或完全稀疏状态，也没有新增执行图缓存。下一层架构工作是将逻辑域与物化字段进一步分开、让内部状态按需存储，同时完整保留逐行 patch、迁移、回读及密集回退；这些语义不能交给用户通过添加 grid 或更换求解模型来弥补。
