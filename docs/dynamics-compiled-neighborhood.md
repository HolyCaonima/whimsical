# 集合算子的物理布局与执行优化

2026-09-13。修改范围仅为 dynamics compiler；用户 DSL、项目输入、求解预算保持原样。

## 编译目标与已落地的变化

目标是从集合上的数学表达式推导出接近手工 GPU 邻域程序的存储与执行结构。编译器不识别物理对象类别，也不匹配项目名称。

现有分析已经能证明一类标量表达式具有以下结构：

```
C_i = a * sum_j f(||q_i - q_j||², p_i) + b(p_i)
g_ij = 2 a f' * (q_i - q_j)
J_ii = sum_j g_ij, J_ij = -g_ij
```

本次沿用这些代数证明以及有限支撑、互反且单射的端点映射、恒等切空间导数等适用条件，改变它们的物理 lowering：

1. **共同的内部排列。** 空间桶构造完成后，将每个桶的成员压入连续区间，建立逻辑 ID 与物理位置的双向映射。候选表、状态快照、算子行和累计修正共享物理顺序。公开变量与关系 ID 不变。桶内构造仍用链表，但反复执行的矩阵作用不再追踪链表。
2. **先因式分解，再选择缓存。** 每条边只缓存标量 `k = 2 a f'`，使用共享状态快照重建 `g = k * delta`，替代三个分量的梯度缓存。候选 ID 和系数采用匹配短归约组的分块布局。
3. **编译期证明累计修正的独占写入。** 将集合 lowering 推迟至着色与普通 Jacobi 依赖统计之后。只有全部输出变量均无其他集合域或普通 Jacobi 写入者时，才能采用私有累计修正，并删除第一次矩阵作用中已知为零的 `J * delta`。无法证明的域保留共同累计路径。
4. **融合最后一次归约与状态更新。** 独占域的最后一次归约直接调用用户空间定义的 `retract`。所有邻居读取均来自不可变快照，避免边写状态边读邻居的竞争。公共累计槽同时清零，通用 apply 阶段排除这些变量。没有将 `retract` 偷换成固定的向量相加。
5. **版本化候选关系。** 位移检查产生候选失效代数，线性化消费者确认完成的代数，取消独立的失效标记重置 dispatch。复用条件仍采用原有的位移证书；状态和导数每轮更新。

物理缓存始终按声明的分量顺序存储。支撑分析可能排列投影坐标，不能把该排列直接当作状态或切向量顺序。

最终结构为：

```
着色阶段
  -> 位移检查 / 必要时重建连续桶区间与候选表
  -> 在共享状态快照上完成线性化与活动依赖统计
  -> 标量行求解 -> 按输出变量归约
  -> 后续矩阵作用与归约
  -> 最后归约 + 用户 retract
```

## 测量

设备 NVIDIA GeForce RTX 3080，Release，Vulkan 验证开启。使用已有的 `captures/sum-layout-sep13/settle.js`，串行运行修改前保存的可执行文件和最终可执行文件，没有同时运行其他基准。每次 1800 步，模拟时长 60 秒。

输入仍为当前项目的 10,000 个成员，Hybrid，`dt=1/30`，4 个子步，12 次非线性迭代，每次 4 次线性扫描，`colorBudget=12`。计时为完整 Dynamics GPU 提交的时间戳区间，不含渲染；下表的长程测量未开启详细 profiler。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 第 31–180 步平均 GPU 时间 | 11.369 ms | 8.169 ms |
| 最后 180 步平均 GPU 时间 | 11.320 ms | 8.054 ms |
| 每步 dispatch 数 | 876 | 828 |
| 无效求值 / 奇异系统计数 | 0 / 0 | 0 / 0 |

末段耗时降低 **28.85%**，吞吐提升 **1.406 倍**。这不是百万规模测量，不能据此声称达到 100 万成员 / 4 ms。

单独运行已有 `profile.js --profile`，取最后五个物理提交的详细 profile 平均值，用于定位收益，不与无 profiler 的总时间混用：

|---|---:|---:|
| 候选索引 | 1.174 ms | 1.207 ms |
| 线性化 | 1.997 ms | 1.461 ms |
| 首次行求解 | 1.128 ms | 0.667 ms |
| 后续行求解 | 2.889 ms | 1.914 ms |
| 所有归约与最终 apply | 3.984 ms | 2.497 ms |

连续分组本身没有显著降低索引成本；主要收益来自后续消费者使用共同布局、减少边数据和合法消除执行阶段。

## 与目标仍有的距离

当前仍有每步 48 次非线性线性化、192 次线性扫描以及相应全局依赖，不能单靠内存排列把它们解释为手工程序的少数几个 kernel。预算来自既有求解策略，本次没有通过减少迭代、替换梯度或改变输入表达式来制造加速。

大域沿用受存储预算约束的流式邻域遍历，连续桶区间可供它使用，但尚未实测百万规模。它仍会反复读取邻域，距离跨行分块复用、减少全局同步的编译结构有明显差距。

候选表超过 128 项时，仍保留原实现的完整遍历和单次线性扫描数值回退；没有截断邻居，也没有在本次悄悄改变该有限预算行为。长期应把“候选存储溢出”和“线性求解策略”从架构上解耦，使存储选择不再改变扫描次数。

进一步的方向是将当前生成器中的布局、快照版本、读写所有权与阶段依赖提升为可组合的算子表示，再据此选择跨行分块、缓存与融合。它们需要从表达式和依赖事实推导，仍不需要物理对象分类。

## 参考的机制

- [Warp SPH 示例](https://github.com/NVIDIA/warp/blob/main/warp/examples/core/example_sph.py)：观察其邻域工作顺序与状态访问形状；没有复制它的物理求解公式。
- [Simit](https://people.csail.mit.edu/jrk/simit.pdf)：用索引表达式连接图计算与稀疏线性代数，优先组合算子而非无条件物化矩阵。
- [Ebb](https://sing.stanford.edu/site/assets/publications/ebb-tog2016.pdf)：关系和分组索引作为布局与遍历的依据。
- [AsyncTaichi](https://mingkuan.taichi.graphics/publication/2020-asynctaichi/asynctaichi.pdf)：利用状态版本与依赖推导冗余工作的消除。
