# 集合关系：双向稀疏布局与有界候选复用（2026-09-13）

当前 10,000 规模示例的稳定阶段，完整 Dynamics GPU 提交从 **47.614 ms 降到 19.154 ms**，约 **2.486 倍**吞吐、耗时减少 **59.77%**。优化前后各运行 1,800 tick（60 秒模拟时间），使用同一份项目 DSL、初值、参数、1/30 秒 tick、Hybrid / 4 子步 / 12 次外迭代 / 4 次缓存线性迭代。

修改仅在 `engine/physics/dynamics/compiler`。Model、Adapter、Runtime、RenderCore、项目脚本和 tests 均未修改；已重编译实际应用。编译器没有新增任何具体物理对象、关系名称或项目名称分支。

## 瓶颈和编译结果

原路径把每条关系的修正散射到自由度，使用 compare-and-swap 模拟浮点原子加。密集关联下，四轮缓存线性求解都在争抢相同的输出地址。分项采集中，散射约占计算阶段的 56%；增加线程并没有消除输出冲突。

现在从同一集合关系生成两个稀疏视图：关系行读取 J 以计算 `J Δq`，自由度列读取加权转置以计算 `M⁻¹Jᵀ Δλ`。后者由一个 32-lane 团队归约，每个自由度只有一个写入者。多个域仍按原来的顺序执行；原流式回退产生的贡献也继续参与累计。

```text
用户 Formula + 集合绑定 + 有限支撑证明
    ↓
检查候选域的位移界
    ├─ 失效：建立投影索引和候选列表 → count / scan / transpose
    └─ 有效：复用候选列表、CSR 和两种视图之间的 entry map
    ↓
当前状态求值、AD、别名合并、有效质量块
    → 直接写入当前 J 和加权转置；重新统计活动度
    ↓
四轮 [关系行线性求解 → 自由度列归约]
    ↓
原 Gather / retract 更新真实状态
```

CSR 描述候选关联，独立于本轮是否启用、是否满足不等式以及导数是否为零。系数每次重新计算；不活动行清空瞬时乘子增量，别名和零导数条目清空对应系数。因此，复用拓扑不等于复用过期的线性化结果。

布局由消费者的访问模式决定：

- 关系的矩阵、右端项、乘子基值与瞬时增量采用紧凑列布局，避免读取一个乘子时跨越整条有界成员缓存。
- J 在关系行内按系数分列，成员线程连续读取同一系数；加权转置按 CSR 列连续存储，归约不再追逐远处的关系记录。
- 投影索引的 cell key、链指针和特征坐标放在同一个 8-word 记录中，改善随机成员访问的局部性。公开状态仍使用原 SoA 地址。
- 每个线性化快照只归约一次活动度上界，后三轮复用它；线性残差和乘子仍逐轮更新。

## 候选复用的条件

由 `supportBound` 证明原表达式及导数在半径 R 外为零。编译器生成约 1.05R 的候选域，并保存构建时两侧的投影坐标。每次颜色阶段之后，检查所有锚点和成员相对该快照的位移。

两侧位移均不超过 0.024R 时，当前距离不超过 R 的任意配对，在旧快照中的距离不超过 `R + 2×0.024R = 1.048R`，仍在保存的候选域中。余量用于浮点计算。半径变化、无效坐标或位移超过界时重新建立索引。参数的其他变化不复用公式值、导数、metric 或 enabled 状态。

列表容量仍为 128。溢出或无法索引的行完整遍历逻辑域，不截断数学关系；这些行不进入转置 CSR。扩大候选域可能让接近容量的输入更早回退，本轮没有实现动态列表扩容。

缓存选择仍要求 Auto、活动权重、有限支撑和可写成员映射单射。共享内存预算保持 8 KiB；SumData 的总编译预算为 96 MiB，包含正向缓存、转置和索引。当前示例该缓冲区约从 45.0 MiB 增至 55.3 MiB。超预算、无法证明支撑或映射不满足条件的输入继续走原流式路径。工作组归约使用普通 shared memory 和 barrier，不要求固定 Vulkan subgroup 宽度。

## 参考系统与采用的机制

- **Ebb** 的关系 GroupBy 用隐藏的反向索引执行 query-loop，并以列存储实现 GPU 字段访问。本次把求和关联编译为内部 CSR，用户无需提供反向邻接表。[论文 §6.1](https://sing.stanford.edu/site/assets/publications/ebb-tog2016.pdf)
- **Simit** 利用图和矩阵的对应关系实施原位计算、owner-computes 和索引表达式融合。本次从同一绑定域生成正向与转置视图，线性化直接写入消费者需要的布局。[论文 §9](https://commit.csail.mit.edu/papers/2016/simit.pdf)
- **Taichi** 将存储布局与计算分离；其非规则访问实验说明布局必须匹配访问模式。**AsyncTaichi** 基于跨 kernel 的数据依赖消除重复工作。本次分别处理候选结构的有效期和数值系数的有效期。[Taichi §6.1](https://yuanming.taichi.graphics/publication/2019-taichi/taichi-lang.pdf)、[AsyncTaichi](https://arxiv.org/abs/2012.08141)
- **Newton / Warp**：Newton 基于 Warp。Warp 的编译器可以把浮点原子累加改写成按目标分组的归约；这是保留前端输入、改变后端执行形式的参照。本实现依据已有关系直接建立可复用索引，没有引入排序库、CUDA 后端或确定性保证。[Newton 仓库](https://github.com/newton-physics/newton)、[Warp 编译期归约改写](https://nvidia.github.io/warp/latest/user_guide/execution_and_performance/deterministic_execution.html)

Ebb 的 FluidsGL 使用规则网格和 CUFFT；它与当前集合约束不是同一种离散算法。旁边 40,000 规模示例也不是同等数学工作量。这里迁移的是编译和执行机制，没有用其他模拟算法替换用户公式。
