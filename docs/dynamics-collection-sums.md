# 关系表达式中的集合求和

关系可以直接写：

```js
var density = op.sum(contribution, b);
```

`contribution` 是已有标量或向量运算构成的表达式，`b` 是 `defineRelation` 回调收到的形式对象。求和产生另一个表达式，可以继续构造残差或 history 更新。无需额外声明密度自由度，也没有新增 `W`、核函数或流体专用接口。

下面的完整关系定义要求每个 `a` 与所有绑定的 `b` 之间的差之和为零：

```js
var balance = X.defineRelation({
    name: 'sum balance', objects: [{u: R3}, {u: R3}], rows: 3
}, function(op, a, b) {
    return {residual: op.sum(op.vsub(a.u, b.u), b)};
});
X.pair(balance, anchors, members, []);
```

## 绑定及数学语义

- `op.sum(value, b)` 保留左侧成员索引，每个左侧成员产生一个关系实例；`op.sum(value, a)` 同理保留右侧索引。
- 普通向量求和逐分量进行。同一个残差可以包含多个求和项，并在外层使用非线性运算。
- pair 的原有组合规则决定成员域。不同集合取完整积；同一集合的 `directed` / `undirected` 和 `includeSelf` 规则仍然生效。例如对 `b` 求和时，无向且排除自身的域是 `b.index > a.index`，不是整个集合。
- 单体的求和域包含一个成员；空集合及三角域的空边界求和为零，保留另一侧的关系实例。
- 求和按对象成员计数。多个成员或字段引用相同自由度时，贡献仍分别计入；对该自由度的导数合并后参与求解。
- parameters、compliance、enabled、history、乘子均按求和后的关系实例排列。多个 pair 的结果按绑定顺序拼接。

C++ 的对应运算为 `sum(Scalar, objectIndex)` / `sum(Vector, objectIndex)`，索引为 0 或 1，关系通过具名对象 schema 和 pair 绑定提供成员域。场景文档把该运算保存为 `sum` 节点，第二个参数是绑定索引，不是另一个算术节点。

## 编译与执行

Compiler 将公式在求和处拆成被求和表达式和外层表达式，复用现有自动求导，并以链式法则组合导数。同一自由度出现在多个成员、多个字段或求和两侧时，先合并导数，再形成约束的有效质量矩阵；使用现有空间的切空间映射、inverseMetric 和块求解。

Compiler 根据成员映射、有限支撑和资源预算选择流式遍历或工作组并行线性化。后者在寄存器中保留成员导数，通过共享内存累计求和值和保留侧导数，活动度与局部求解复用同一快照的线性化结果，再按成员并行散射。成员映射与重复引用表按源集合大小保存，不物化笛卡尔积端点表或完整跨成员 Jacobian。具体执行边界与性能对照见 [2026-09-13 优化记录](dynamics-compiler-sums-sep13.md)。

缓存路径在每次非线性快照内进行四轮耦合线性求解，用 J、累计切空间位移与当前乘子更新线性残差；真实状态仍在原 Gather 阶段更新。它保留用户的时间步与外迭代预算，改善有限预算内的收敛，不保证与单轮路径逐位相同。当前资源边界及长时间验证见 [线性求解与显示统计修正](dynamics-sum-convergence-sep13.md)。

Auto / Active 权重在当前 Jacobi 快照上统计实际参与求解、且合并后切空间导数非零的自由度。统计与求解都在 Colored 阶段之后执行，所以它们使用相同的位置。远处的零贡献不再把密度修正按整个集合的大小缩小；显式选择 Static 时仍保留静态关联计数。

Compiler 可以从 `max(0, radius² − distance²)`、`max(0, 1 − distance² / radius²)` 及其乘积等表达式证明有限支撑域，复用候选域的哈希网格操作枚举成员。半径由参数表达式在 GPU 上计算，参数补丁使其失效；索引每轮在当前位置重建。成员列表容量有限，但逻辑域不截断：列表溢出、半径或坐标无法索引时，回到完整成员遍历。无法证明范围的表达式也保留完整求和。

当前实现范围：

- 一个关系可包含同一侧的多个求和，残差与 history 更新共用该侧；暂不支持嵌套求和或同时对两侧求和。
- 被求和对象的字段只能在求和表达式内部引用。另一侧字段可以在内部和外部引用。
- 支持静态 Hybrid / Jacobi 模式；求和关系使用 Jacobi 阶段。纯 Colored 模式、与动态端点拓扑混合的模型会明确报错。
- 含求和的计划保留全局快照阶段；求和之前的固定端点颜色阶段可独立融合，求和自身按上述规则映射工作组。求和可索引不超过三个输入差坐标，多个求和项目前需共享同一支撑域证明。history 更新使用更新时的完整成员域；无法证明支撑域时，计算量仍随两侧成员数乘积增长。

不含求和的计划保留原来的调度和候选域路径。ConstraintLab 新增独立的 [Fluid 示例](../Projects/ConstraintLab/Content/scripts/fluid.js)，原有集合粒子示例保留。

## 验证

`DynamicsTests.cpp` 将左右两侧求和分别与显式展开的相同约束比较，覆盖多个求和、外层非线性、重合自由度、实例计数和 history 更新。`DynamicsSum.js` 验证实际 DSL、只读成员、空集合，以及带非对角 inverseMetric 的向量块求解。两者通过 CTest 的 `dynamics_solver` 和 `dynamics_sum_dsl` 运行。

有限支撑域检查使用 160 个自由度构成相互远离的二元组，验证第一次修正的解析值，确保远处成员不稀释权重；再修改半径使列表溢出，与禁用索引的完整求和逐项比较，覆盖参数失效及精确回退。
