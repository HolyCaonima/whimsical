# 集合算子 IR 与执行重构

2026-09-13，基线 `19c10ba`。修改限于 Dynamics compiler、构建清单及文档。用户 DSL、项目输入、空间、残差、参数、compliance、history、retract、子步数和外层迭代数均未修改。没有新增测试，没有使用 subagent。

在 RTX 3080 上，原始一万规模的末段完整 GPU tick 均值从 **6.511 ms 降到 4.130 ms**；既有百万规模驱动的 12 步均值从 **1202.868 ms 降到 266.794 ms**，约 **4.51 倍**。百万规模仍未达到 4 ms。

## 分离数学、数值方法和存储

新增 `CollectionOperator.h/.cpp`，从绑定映射和表达式中分析：单射互反映射、标量归约、有限差分支撑、径向标量因子、恒等切空间导数，以及外层表达式的常数线性系数。分析结果不含 GPU 地址、候选容量或物理类别。

适用形状为：

```text
C_i = a * sum_j f(||q_i-q_j||², parameters_i, history_i, h, time) + b_i
g_ij = 2a f' * (q_i-q_j)
J_ii = sum_j g_ij,  J_ij = -g_ij
```

这是表达式及映射的证明条件，不是名称识别。非均匀参数或 history 存在时，转置遍历仍计算反向行的因子；只有参数模式证明一致且没有 history 时，才能利用系数互反性。支撑和参数派生量的有效期继续由原有参数更新路径维护。

`CollectionSolvePlan` 表达线性化、前向作用、转置作用、二次型归约和应用更新。`Compiler.cpp` 按这些动作及其阶段编号安排各域，移除了顶层编译器里固定追加三轮 refinement 的写法。旧的显式 Jacobi/Active 路径仍保留，包括固定表长行的历史兼容行为；新投影路径的缓存和流式行使用同一个数值方法。

`SumRelations.cpp` 随后选择索引、候选表、线程归约组和暂存布局。用户定义的自由度和关系仍是唯一数学输入。

## 两次邻域遍历形成一个耦合下降方向

这不是逐位等价的调度优化。Hybrid/Auto 且算子独占修正场时，求解器更换了线性化问题的迭代方法。显式 Jacobi、其他权重策略、共享修正场及不满足代数条件的关系继续使用原路径。

令 B 为用户逆度量，alpha 为 compliance/h²，lambda0 为本次线性化的乘子：

```text
A = J B Jᵀ + diag(alpha)
r = -C - alpha * lambda0
D = diag(A)
d = project(lambda0 + relaxation * D⁻¹ r) - lambda0
z = Jᵀ d
u = B z
numerator = rᵀ d
curvature = zᵀ B z + sum_i alpha_i d_i²
omega = clamp(numerator / curvature, 0, 1)
lambda = lambda0 + omega * d
q = user_retract(q0, omega * u)
```

投影沿用用户关系的等式或不等式方向。由于线段两端的乘子均可行，omega 在 [0,1] 内保留乘子可行性。omega 最小化的是这条方向上线性化问题的二次型，不能把它称为整个非线性问题的最优解。

第一次邻域遍历生成残差、对角预条件、固定端梯度和投影方向。第二次按输出所有者归约转置，同时累计二次型的两个标量。多项先在线程内累加，再做工作组和全局归约。这样不必为了求曲率再做一次 J 的邻域遍历，也不必物化稀疏 Jacobian 或其转置。

原输入仍执行 4 子步 × 12 外层迭代；每轮从最多八次邻域访问降为两次。用户的原导数保留，没有换用手写流体实现中常见的另一种梯度核。

## 从所有权和访问模式选择执行形状

短归约组使用 8 个 lane。坐标快照与行增量共同采用四字布局，私有累计修正不再在中间阶段镜像到公共 contributions。参数派生量和行历史在进入邻域循环前装载；统一启用且单位逆度量的路径可在解析邻居逻辑地址前返回结果，其他度量和启用模式继续按用户字段求值。

新增 `OwnerTransform` 描述一个完整所有者状态的点式消费者。`Schedule.cpp` 仅在所有权域完全一致时，将快照发布和失效检测接到已有局部关系链的末尾。所有者状态可直接从寄存器写入快照；不存在匹配证明时，保留独立阶段。

索引按域规模选择两种物理形式：短域将独立哈希桶一次性打包；大域用计数、并行前缀和及散射形成空间次序。包围格子的体积能装入桶预算时使用三维稠密线性次序，否则使用哈希次序并核对完整单元坐标。公开逻辑 ID 始终稳定。

一万规模的常规 tick 从 684 个 dispatch 降到 **444 个**，最终 profile 验证了该数量。实际执行图为：

```text
所有者关系链 + 快照
  -> 必要时更新空间索引与候选表
  -> 线性化 + 投影方向
  -> 转置归约 + 二次型分量
  -> 步长归约
  -> 用户 retract
```

跨行依赖仍有明确的全局阶段边界。没有在单个 shader 中引入隐含的跨工作组同步。

## 候选行的有效期不再等同于整个索引

百万规模中间版本的后段 profile 显示，约 500 ms 用在全域候选计数和填充，实际两次算子遍历合计约 70 ms。一个局部移动会触发全集合重建，这是比少量算术操作更大的结构问题。

新投影路径在大于 32,768 行时选择跨重排保留的候选缓存：

1. 候选表按逻辑行寻址，保存逻辑成员 ID；读取时经过当前排列映射。空间索引重排本身不再使这些候选失效。
2. 每个成员有移动参考，每个哈希桶有最近修改版本。参考移动超过 delta=0.024R 时，标记旧、新桶；碰撞只会造成额外重建。
3. 每行保存候选生成时的位置和版本。当前行验证自身位移和完整邻近桶版本；只有失效行重新搜索候选。有效性检查分配到查询组的各 lane。
4. 行区域采用稳定偏移，避免紧凑前缀变化迫使其他缓存行搬迁。根据存储预算选择每行容量，最多 128 项。容量不足的行完整遍历空间索引；不截断候选，也不降低该行的求解次数。

保守界包含了不同参考时间：在没有相关桶修改的情况下，成员相对候选生成时最多移动 3delta；锚点包含未重建索引的阶段，最多移动 2delta。总和为 0.12R，所以缓存采用 0.13R 外扩，格子边长为 1.1302R。新进入支撑域且发生过移动标记的成员，其最新参考桶必在检查范围内。R 是所有行的保守支撑上界。支撑尺度或无效索引状态变化会重置缓存有效期。

空间索引本身仍可能全域重建，所有行也仍要检查候选有效期；这里尚未实现失效行的间接 dispatch。该缓存的容量选择采用 1 GiB 的 SumData 预算，模型字段和其他缓冲区另计，不能把这个数当成总显存占用。

## 百万规模与剩余限制

复用既有 `captures/operator-plan-sep13/million.js`，同一套关系、支撑、间距、compliance 和求解预算，使用扩大的集合与容器；它不是原始一万场景的同一初态。

| 完整 GPU tick，12 步 | 基线 | 最终版本 |
| --- | ---: | ---: |
| 全部 12 步均值 | 1202.868 ms | 266.794 ms |
| 最小值 | 578.007 ms | 153.862 ms |
| 最大值 | 1669.151 ms | 403.077 ms |
| 第 12 步 | 1669.151 ms | 403.077 ms |
| invalid / singular | 0 / 0 | 0 / 0 |

这里没有百万规模的长期完整状态误差检查，诊断为零不能代替该检查。该运行主要说明执行成本和扩展性。数值方法改变后轨迹不完全相同，因此这个倍率也不是严格同轨迹的单纯 kernel 加速倍率。

**百万规模 4 ms 尚未达到。** 仍有每 tick 48 轮全域非线性迭代、96 次完整算子邻域访问，候选有效性检查和重建成本仍随运动增长。尚需解决跨行的空间块复用、有效行工作队列及更强的耦合求解收敛；不能把某个内层阶段的时间当成完整模拟 tick。

本轮也测量了单线程归约行、直接流式查询，以及利用差分表达式平移不变性的内部移动原点。它们在所测路径没有净收益，未作为新的执行选择保留；完整流式遍历仍作为存储回退存在。

相关经验落实在不同层级，而非移植某个物理模型：

- [Simit 原论文](https://commit.csail.mit.edu/papers/2016/simit.pdf)：按输出归属并行化及索引表达式融合，启发算子作用和存储解耦。
- [Ebb 原论文](https://sing.stanford.edu/site/assets/publications/ebb-tog2016.pdf)：内部关系索引和分组布局。其 FluidsGL 示例使用网格与 FFT，不能直接当作本例的同工作量性能基线。
- [Taichi 性能文档](https://docs.taichi-lang.org/docs/performance) 与 [AsyncTaichi](https://mingkuan.taichi.graphics/publication/2020-asynctaichi/asynctaichi.pdf)：布局独立选择、局部归约，以及按状态有效期减少列表重建和阶段执行。
- [Newton 官方教程](https://newton-physics.github.io/newton/1.2.0/tutorials/00_introduction.html)：通过 CUDA graph capture 降低循环提交开销。当前 Dynamics 已按一条 GPU 序列录制；本轮 profile 指向候选搜索和数值工作量，故主要重构编译结果，而非继续围绕 CPU 提交做优化。
