# 从表达式和访问形状选择执行计划

2026-09-13。本轮基线为 `81f7b80`。修改限于 Dynamics compiler，用户 DSL、项目脚本、关系公式、空间定义和求解预算均未修改。没有增加测试，也没有使用 subagent。

原始一万规模的完整 GPU 单步末段均值由 **7.957 ms 降至 6.609 ms**，耗时减少 **16.93%**。本轮没有达到百万规模 4 ms；大规模实验仍暴露了反复全域邻接扫描的根本成本。

## 编译器实际改变了什么

### 1. 按写入归属融合关系链

`Schedule.cpp::fuseOwnedRelations` 检查着色前缀中每一条关系：所有非只读端点必须指向同一个自由度。满足条件时，各自由度之间不存在状态读写依赖，可以保留各自原有颜色顺序，把整条关系链交给一个 invocation。

相同的空间和 kernel 调用序列共享生成程序。自由度状态只在入口读入寄存器、出口写回；只读输入、历史、参数和乘子仍使用原接口。不按关系名称、物理类别或参数数值分类，也不假定空间的 retract 是向量加法。不满足证明条件的计划继续采用已有调度。

### 2. 按表达式依赖划分计算有效期

`FormulaGlsl.cpp::stageFormula` 将 DAG 中只依赖不变量的最大子表达式切出，其输出成为内层表达式的新输入。

集合算子的 lowering 将参数作为外层不变量，把状态、历史、时间、步长与平方差保留在内层。参数派生量在已有参数边界计算阶段生成，参数 patch 会刷新它们；没有增加每次线性化的预计算 dispatch，也没有冻结随状态变化的导数。该分割由依赖关系决定，无须在编译器中识别任何物理核函数。

### 3. 用结构上界构造对角预条件，并融合第一次更新

已有分析证明的适用形状仍为：

```
C_i = a * sum_j f(||q_i - q_j||², p_i) + b(p_i)
J_ii = sum_j g_ij, J_ij = -g_ij
g_ij = 2 a f' * (q_i - q_j)
```

还要求单射且互反的端点映射、有限支撑、恒等切空间导数等原有条件。只有该算子独占累计修正且 weighting 为 Auto 时，才选择新的预条件方式；显式 Active 保留原有活动度权重。

令 `n_v` 为候选关系对自由度 v 的入度上界，`B_v` 为用户定义的逆度量，`alpha_i` 为原 compliance 除以步长平方。互反关系使候选行长度也能界定列入度；不含自身的关系需额外计入其对角项。取：

```
H_i = alpha_i + sum_v n_v * J_iv B_v J_iv^T
```

由 Cauchy–Schwarz，对任意 z：

```
z^T J B J^T z
 = sum_v ||sum_i B_v^(1/2) J_iv^T z_i||²
 <= sum_i z_i² * sum_v n_v J_iv B_v J_iv^T
```

因此 H 是线性化系统的对角上界。后续仍求同一个残差 `b - J*dx - alpha*(lambda-lambda0)`，沿用乘子投影、relaxation、四次线性扫描与用户 retract。改变的是预条件及有限预算下的迭代轨迹，并非逐位等价的调度优化。

候选上界在线性化之前已经可用，因此可删除活动度清零、第二遍活动关联统计以及独立的第一次行求解，将第一份乘子增量直接在线性化中发布。原始一万规模每步 dispatch 从 **828 降到 684**。

### 4. 小域分块表、大域紧凑表

根据索引与标量系数的预计存储量选择布局。小域保留原来适合短归约组的固定分块表；大域改用计数、分层并行前缀和、填充形成连续行区间。ID 与标量系数采用相同边偏移。

紧凑表共同分配容量，初始目标为平均 64 项，受约 640 MiB SumData 预算约束；这个平均数不是每行上限。长行可以使用完整区间，容量耗尽的行完整流式遍历。前缀和在预算外饱和，避免分配地址溢出。新紧凑路径的缓存与流式路径均执行完整的四次线性扫描。

旧固定表超过 128 项时的单次扫描回退仍保留，这是已有数值检查约束的兼容行为。本轮没有把该历史差异推广到新紧凑布局，也没有截断邻接。

移动失效检测改成工作组内归约后更新版本计数。索引各阶段具有独立 profiler 名称，便于分辨重建、计数、扫描和填充成本。

最终计划的形状为：

```
独占关系链：读状态 -> 按原顺序调用关系 -> 写状态
  -> 更新状态快照 / 检查候选有效期
  -> 必要时重建索引与候选表
  -> 线性化 + 对角预条件 + 第一份乘子增量
  -> 按输出归约修正
  -> 三轮：作用 J -> 更新乘子 -> 作用 B J^T
  -> 最后一次归约同时调用用户 retract
```

跨行依赖仍需要全局阶段边界。没有把所有阶段强塞进一个带隐含全局同步的 shader。

## 大规模实验与未解决的问题

另建独立测量驱动，调用同一组用户关系定义、支撑半径、间距、compliance、重力与迭代预算，扩大初态集合及容器。它没有修改项目脚本，也不是原始一万场景的同一初态。百万规模运行仅用于执行与扩展性观察，未计算完整长程状态误差。

一次 97,336 成员的逐阶段对照中，全局 CAS 邻接分配版本的第二步约 79.68 ms，其中候选生成约 40.61 ms。改为并行前缀分配后，该步约 48.29 ms，候选计数与填充合计约 10.09 ms。这里比较的是本轮中间版本，不是原始基线；数值归约顺序也可能改变，不能当成严格同轨迹加速比。

最终百万规模完整执行 12 步，GPU 单步为 **593.6–1785.1 ms**，invalid / singular 为 0 / 0，并未接近 4 ms。完整计划仍有每步 48 次非线性线性化和 192 次线性扫描；即使按每行约 40 个候选估算，八次邻域访问乘以 48 轮也达到约 153.6 亿次逻辑边访问。实际工作量还随活动比例、密度、候选复用及缓存行为变化。这一计算不是硬件耗时下界，但揭示了现有全域迭代形状的成本，无法用少一次提交来消除。

还需要从代数和依赖出发处理跨行分块复用、真正的空间局部顺序、算子求解策略与有效工作量。连续的哈希桶区间不等于空间连续顺序；对每行的局部融合也不等于整个耦合系统已完成融合。本轮没有实现这些后续结构。

实验过的全局 CAS 分配器以及把修正向量合并存储的布局均未保留。后者在本次测量中没有稳定收益，小规模还有回退，最终继续使用原列式算子状态。
