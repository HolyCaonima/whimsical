# Dynamics 候选域编译与收敛优化方案

2026-09-11。已在用户授权的 dynamics/compiler 范围内实现第一阶段及后续执行优化，DSL 输入未变。以下保留实施前的设计分析；后续优化一节更新第一阶段的队列、清理和索引执行方式。调查时 Whimsical 基线为 `499a22acc8466cf1bf3fe2fb2894a52e0757ad59`。

## 结论

下一步应该把集合关系编译为“逻辑域 + 可证明的候选查询 + 数值活动集”，让执行器遍历可能产生作用的组合。现有 BindingIR 已经保留集合域，但仍在逐逻辑关系分配、着色、初始化乘子和调用求解函数。继续优化单次 residual/Jacobian 不能消除全连接集合的平方增长。

同时，当前 Jacobi 使用全部静态 incidence 作为缩放分母。高候选数、低活动率模型因此不仅检查大量无效关系，还把有效关系的修正显著缩小。候选筛选和数值缩放需要独立实现、独立对照，不能把改变收敛轨迹包装成等价编译优化。

所有新增分析只消费数学表达式、集合索引、读写效果、求解状态和后端成本。用户继续定义自由度、坐标映射、关系和连接。Compiler 不识别对象名称、字段名称或项目类别，也不增加任何具体模拟对象的内建求解器。

## Newton 中哪些经验适用

参考源码固定为 Newton v1.5.0，提交 `cca3bb8a17a3620a1343df3cf12c625e4161b317`。本轮读取了实际 Git 源码，以免把不同版本搜索结果混在一起。

- XPBD 的邻域路径先按 hash grid 找候选，再判断实际距离，按查询端点汇总修正。查询顺序与 cell 排列相关。可迁移的是候选查询和内存局部性；其具体对象字段、摩擦模型和修正公式不能搬进我们的编译器。[XPBD kernels](https://github.com/newton-physics/newton/blob/cca3bb8a17a3620a1343df3cf12c625e4161b317/newton/_src/solvers/xpbd/kernels.py)
- 该版本在积分后建 grid，随后进行求解迭代；该路径按配置 relaxation 应用邻域修正，没有使用我们这种全部逻辑配对 degree。我们不能直接复制它的 grid 更新频率：我们的通用 retract、其他关系修正和乘子持续状态要求单独证明候选有效期。[SolverXPBD](https://github.com/newton-physics/newton/blob/cca3bb8a17a3620a1343df3cf12c625e4161b317/newton/_src/solvers/xpbd/solver_xpbd.py)
- `example_mpm_granular.py` 使用隐式 MPM；这里 grid 是离散计算空间，改变 voxel size 会影响数值模型。例子暴露 tolerance、max iterations、稀疏/固定 grid 等选项，部分几何检查也允许 voxel-size 量级的偏差。我们要借鉴它把离散误差与求解误差分开的方式，不能把 MPM 当作 pair XPBD 的等价加速实现。[Granular 示例](https://github.com/newton-physics/newton/blob/cca3bb8a17a3620a1343df3cf12c625e4161b317/newton/examples/mpm/example_mpm_granular.py)
- Warp 的 HashGrid 是候选生成器，hash 碰撞可能返回额外候选，调用方仍需精确判断。cell 宽度是查询成本参数，不是关系含义。[Warp HashGrid 文档](https://nvidia.github.io/warp/v1.5/modules/runtime.html#hash-grids)

## 建议的架构

```text
用户 Formula + BindingIR + 结构读写效果
    ↓
公式分析：证明“不满足关系时，两个数学特征的差必有有限界”
    ↓
CandidateDomain：逻辑域、特征表达式、边界表达式、依赖、稳定行映射
    ↓
执行映射：完整遍历 / 分桶邻域遍历
    ↓
XPBD 活动集：候选关系 ∪ 仍有非零乘子的关系
    ↓
精确 residual → 活动 incidence → 原局部数学求解 → Gather
```

`CandidateDomain` 是求解器无关的域分析结果；乘子、活动 degree 属于数值后端，不能放进 BindingIR 的集合定义里。空间索引只提供保守候选，最终是否产生作用仍由用户公式及数值后端判断。

### 1. 从公式推导有限候选范围

首批支持可证明的平方和界。例如原始数学表达式

`Σ_k (a_k - b_k)² - s² >= 0`

意味着当它被违反时，每个 `|a_k-b_k| < |s|`。编译器提取的是两个数学特征映射及参数边界，完全不需要知道 a、b 或 s 的名字。反向不等式的等价写法可以在同一分析中规范化。

识别应基于 DAG 运算和输入依赖：允许平方项和加法的不同结合顺序；不依据 relation 名字，不依据输入恰好有三个 float 就推断坐标。首批为小维数纯特征表达式选择网格，更高维或没有有限界的公式保留完整域。

不能从“初始参数相等”推导永远恒定的范围。首批边界仅依赖常量/关系参数；编译或参数 patch 时刷新域内保守上界，数值关系仍读取每行当前参数。对依赖 time、history 或两个端点耦合且不能分离的边界，先保留完整遍历。上界过宽影响成本，不影响数学关系。

浮点证明也是实现条件：查询覆盖要保守扩张并处理坐标到 cell 的舍入范围，不能仅以实数恒等式保证 GPU float 不漏项。无法在该后端数值范围内建立界的域回到完整遍历，不改变公式或静默截断候选。

### 2. GPU 候选域执行

建议首批覆盖现有仿射 Product/Upper 域、标量不等式、静态成员映射和 Jacobi 路径。Colored 的原位更新会改变查询快照，不能未经依赖分析混用。

按特征值生成 cell key，以域作为命名空间，构建固定角色的桶范围/成员索引。索引存原始成员 ID；不搬动公开 SoA，不改变变量 ID、关系 ID、参数 patch、回读或迁移契约。不同域不能因为特征坐标相同就互相连接。

由成员查询邻域，命中后按原 BindingIR 映射恢复逻辑行。Upper 域只产生一次 i<j；Product 保持方向。哈希碰撞只允许增加精确检查，不能遗漏或重复求解同一逻辑行。初版采用每成员遍历候选并调用原关系函数，可避免一个必须按 P 容量预分配的全局候选队列；其负载不均衡是否需要分段工作表，由采样决定。

初版每轮 Jacobi 读取同一状态快照，重建或刷新查询索引；如果前面有 Colored 阶段，应放在其写入之后、Jacobi 求解之前。不要只在 tick 或子步开始建一次而忽略迭代中的修正。以后若复用邻域，需要把最大特征位移、参数范围变化及邻域裕量写成明确的有效期条件。

平均复杂度目标是按成员、桶和实际候选增长；密集聚集、宽半径以及不适合网格的分布仍可能接近平方复杂度，不能承诺 grid 总是线性。

### 3. 乘子、启用与历史的完整语义

已有 guard 的严格条件是“residual 已满足，且 multiplier=0”。因此 grid 外但 multiplier 非零的关系不能丢弃，它仍可能释放已有修正。

每轮工作必须包含邻域候选与前轮非零乘子集合的并集，去重后恰好求解一次。关系离开邻域后仍继续处理，直到乘子归零；不能在退出候选集时强行清零。

子步开始清理上个子步实际触及的乘子记录，并重置工作计数，使未触及行按零乘子理解；避免每轮或每子步重新扫描 P 条记录。稀疏状态映射与逻辑行分开，容量增长/溢出必须有完整执行路径，禁止默默丢关系。

首版可保留现有 dense 参数、history 和 multiplier 存储以控制改动边界，但要明确它只降低执行成本，尚未解决 O(P) 内存。随后再把通用 relation metadata 和 uniform 字段降成域描述，并为数值内部乘子建立稀疏状态；用户 history 的逻辑行和更新语义不随候选变化。具有独立 history-update 的关系不能因为当前不活跃就跳过更新；初版不对这类关系启用候选化更容易审查。

### 4. 活动 incidence 数值策略

增加显式的通用 Jacobi weighting 策略，保留静态关联缩放作为对照。建议在独立策略下，把当轮 enabled 的等式和实际参与求解的不等式形成活动 incidence。

不等式活动条件沿用 residual 违反或 multiplier 非零；端点别名计一次，结构只读不计入可写关联。数值为零的逆度量不作为永久拓扑条件。

先从同一 Jacobi 快照完成活动判断与 incidence 计数，再求解，关系 r 使用

`d_r = max(1, max(activeDegree(v), v ∈ writableEndpoints(r)))`。

缩放仍同时作用于 delta-lambda 和对应状态修正，不能只在 Gather 后除一次而让乘子与状态失配。普通等式、候选不等式和完整遍历不等式共享同一套计数语义，不能只数 grid 邻居而漏掉其他关系。

这会改变有限迭代轨迹。对非线性方程不宣称普遍收敛保证，也不把该策略静默绑到空间索引开关。应比较同等时间下的误差和达到相同误差所需的时间，再决定是否成为 Auto 默认值。

### 5. 计算图与生成代码

候选化后优先复用现有 `KernelFunction`、按需 Jacobian 和稀疏贡献路径。新的阶段只改变 invocation 的来源，避免维护两套数学求解代码。

活动判断之后复用已计算的 residual，避免再次计算相同 primal；共享输入加载和表达式公共子图由数学代码生成统一裁剪。若把活动判断与求解拆成两个 dispatch，需比较缓存 residual 的带宽与重算成本，不能无条件物化全部 Jacobian。

执行图复用单独评估：当前 runtime 每 tick 仍调用 graph reset、compile、record。缓存的键需要包含实际传输/回读范围和动态拓扑操作，不能仅凭固定 substeps/iterations 认定整图相同。本轮候选域可以通过固定 GPU 阶段和动态桶内容运行，不要求 RenderCore 新增物理相关接口。

## 拟修改范围

| 层 | 拟修改 | 边界 |
| --- | --- | --- |
| `compiler/FormulaGlsl.*` 或独立公式分析模块 | 数学特征与有限界分析、公共 primal 使用 | 只分析 DAG，不解析项目含义 |
| `compiler/BindingIR.*` 及新候选域模块 | 连接逻辑域与证明结果，恢复稳定逻辑行 | 不存 XPBD 乘子 |
| `compiler/CompiledPlan.h` | 候选阶段、固定 buffer 角色、显式 weighting 策略及统计 | 不新增高层对象种类 |
| `compiler/Compiler.cpp` | 选择候选执行、避免无意义的完整着色、生成查询计划 | 显式 Colored 不被偷偷改成 Jacobi |
| `compiler/Schedule.*`、`Kernels.cpp` | 索引刷新、候选/活动遍历、计数、原求解函数调用 | 保持阶段读写依赖 |
| `runtime/Instance.cpp` | 执行新阶段、参数 patch 后刷新范围、临时状态生命周期 | 不改变公开 ID 和读取规则 |

候选域与活动缩放可以分别开关与交付。先保持同一数值划分完成候选域语义对照，再开启活动缩放评估误差。该顺序可防止把性能收益和数值变化混为一谈。

## 已实现的第一阶段（2026-09-11）

入口是 `lowerCandidateDomains()`，消费已经确定的全局静态 Jacobi 批次。`FormulaGlsl::differenceBound()` 只识别 DAG 中的平方差之和及参数边界，支持 1–3 个原始输入分量、两种不等式方向和加法结合次序。Product、Directed、Upper、UpperDiagonal 的仿射字段映射可参与；有 history/update 的域、无法证明有限界的表达式、动态端点及已包含局部融合区域的计划保留原路径。没有对象名称、字段名称或模拟类别判断。

证明与成本选择分开。首轮域分析门槛为 4,096 个逻辑关系；随后用 `P >= 12 × (left × 3^dimension + right)` 比较完整 primal 检查与索引/邻格探测的成本。这个常数是当前后端启发式，并非复杂度或跨设备提速保证。当前 500 自由度示例采用完整并行活动扫描，2,000 自由度采用网格；两者使用同一活动缩放策略。小规模直接建网格的负收益版本没有作为 Auto 的默认选择。

执行顺序为：

```text
参数改变时：GPU 边界归约 → 缓存有限上界
每 tick：初始化候选队列
每子步：原预测
每迭代：原 Colored 阶段 → 刷新索引（若采用网格）
        → 普通关系 / 邻格候选 / 非零乘子旧关系的活动收集
        → 按数学类型消费紧凑队列，调用原局部求解
        → 原 Gather + 下一轮候选清理
每子步末：原速度恢复、原 history update
```

索引存成员 ID 和整数 cell，不移动公开 SoA。哈希碰撞后比较完整 cell，逻辑行位图去重；无向域仍只产生原来的一种方向。每轮从当前值重新建索引，所有活动计数在同一 Jacobi 快照上完成。旧队列中的非零乘子关系会再次进入精确判断，即使已经离开邻格。每个子步清理该域的 dense 乘子；不会把“未查询到”误当成“乘子已归零”。

桶宽采用 `1.25 × sqrt(maxBound)`，缩放坐标限制在 `2^18` 内，并限制原坐标及边界的浮点范围。25% 裕量覆盖该范围内的减法、平方、开方、除法及 cell 舍入误差；超范围、非有限值、过小或过大的边界执行完整域。边界表达式在 GPU 上使用与 residual 相同的 float 代码生成；参数 patch 会使缓存失效，不根据初始参数永久折叠范围。

活动队列按数学类型分区，使一个 workgroup 只消费一种求解函数。已完成活动判定的标量不等式不再重复执行 feasibility primal，也不重复初始化乘子。普通关系的活动收集融合进第一个邻域查询；单 Gather 批次同时清理下一轮计数、位图和桶头。最终稳态 dispatch 数在 500 / 2,000 示例中分别为 157 / 205；原全扫描路径为 108。收益来自工作量与求解收敛，不能只用 dispatch 数衡量。

两个新增固定 buffer 角色保存候选/去重/桶和活动 degree。双队列按完整逻辑 Jacobi 容量分配，密集时没有截断或固定邻居数。参数、history、乘子、relation metadata 及编译期实例仍为 dense，编译时间与内存仍随逻辑组合数增长。每子步乘子清理和每轮位图清理也仍包含 O(P) 工作，尚非端到端线性执行。本轮没有实现稀疏状态存储、GPU 关系扩容、MPM、CUDA 执行图缓存或任意特征映射。没有修改 RenderCore。

原生 `SolverPolicy` 的 `weighting = Static/Active/Auto` 和 `spatialCandidates` 供适用的全局静态 Auto 计划做独立对照；默认值为 Auto / true。`Static + false` 保留原路径，`Active + false` 用完整活动扫描。JavaScript 建模、策略输入解析和项目脚本均未增加入口或字段。场景 plan 摘要仅新增三个输出统计：`candidateDomains`、`candidateRelations`、`activeJacobiRelations`。

## 后续优化：索引复用与活动队列（2026-09-11）

本轮只修改 `BindingIR.cpp`、`CandidateDomains.cpp`、`Kernels.cpp` 和内部 `Schedule.h`。用户 Model、JavaScript DSL 输入、项目脚本、求解策略默认值及 RenderCore 均未改。保留现有公式、Jacobi weighting、颜色划分、子步和迭代次数；以下改变的是编译期索引计算及 GPU 工作的组织方式。

### 参考资料与取舍

- [Simit 2016，第 9 节](https://commit.csail.mit.edu/papers/2016/simit.pdf)：利用图和张量索引间的对应关系安排原位计算，融合索引表达式以消除临时存储。本轮将这一原则用于复用查询已经算出的成员编号和特征 cell，避免成员 → 逻辑行 → 成员的往返转换。
- [Ebb 2016，第 6 节](https://sing.stanford.edu/site/assets/publications/ebb-tog2016.pdf)：底层只实现关系原语，通过列式存储、仿射寻址及分组后的辅助索引支持高层域。这里借鉴关系与执行表示分离、预处理索引及分层归并；没有把 Ebb 的用户域库误当成自动空间局部性证明。
- [Newton v1.5.0 XPBD](https://github.com/newton-physics/newton/blob/v1.5.0/newton/_src/solvers/xpbd/solver_xpbd.py) 与 [Warp HashGrid](https://nvidia.github.io/warp/v1.5/modules/runtime.html#hash-grids)：借鉴邻域候选及后续精确计算的分离。具体物理对象、力学方程和邻域复用频率不迁入编译器。我们的索引继续在每轮 Jacobi 当前快照上刷新。

### 编译与执行

1. **精确三角域反解。** CPU 使用有理化的二次根估计成员行，再以原有 64 位整数前缀校正边界。省去每次 incidence 访问中的二分搜索；逻辑行次序和 ID 保持精确，不依赖浮点近似决定最终映射。
2. **复用已知索引。** 网格查询把已知左右成员传入同一份 `relationActivityFunction` 生成器，仿射端点只读取字段映射，不再反解逻辑行。混合或不适用的寻址模式继续用原入口。数值求解、导数、只读/启用判断均复用既有实现。
3. **每快照缓存 cell。** 索引阶段计算两侧的成员 cell，查询直接读取缓存。只有两侧特征的底层地址映射及成员数相同才共享缓存，不按对象名称或状态宽度推断。两侧任一坐标不满足数值范围时，该域完整遍历。公开 SoA 不移动。
4. **互斥活动来源。** 普通工作表本来只访问每行一次。索引域内，邻域只收集零乘子行，旧活动队列只收集非零乘子行。两个来源消费同一 Jacobi 快照，活动判断不会在后续迭代改写乘子；新的非零乘子只由后续 solve 产生。因此每条逻辑行恰好处理一次，不再需要位图原子去重和每轮 O(P/32) 清理。哈希碰撞仍核对完整 cell；候选离开邻域后的乘子释放继续保留。
5. **按活动队列清理乘子。** 子步边界只遍历完成的队列清零索引域乘子。所有非零乘子都保留在该队列中；已离开队列的行乘子已为零，enabled 也不会在一次提交内部改变。单 Gather 路径在子步末清理，多 Gather 路径在下一子步开始清理。新实例的乘子初始为零。solve 单独发布完成队列的 side，清理只读该 side，避免与其他工作组翻转下一队列发生读写竞争。
6. **类型分组和工作组归并。** 普通活动扫描按数学类型及 128-lane 工作组对齐，直接调用对应谓词。至少一组的工作先在共享内存中计数并取得局部序号，然后每个非空工作组只执行一次全局队列区间申请。小批次保留逐行追加。尾部空 lane 同样经过屏障；所有带屏障的类型范围都完整包含工作组。多行/等式的禁用行仍入队，让原求解函数清理 CSR 贡献，不能简单当作不活动行丢弃。

稳态调度次数保持为 500 规模的 157 次、2,000 规模的 205 次。收益来自去除重复运算、全域清理和全局原子竞争，不是减少数值迭代。网格成本门槛保持原值：500 规模自动完整活动扫描，2,000 规模自动网格；试验性强制小域建网格及限制活动扫描并行宽度没有保留。

### 尚存成本

本轮去掉的是位图和按完整索引域清理乘子的工作，未改变公开字段及关系元数据的 dense 契约。双活动队列仍按最坏逻辑容量分配；2,000 规模计划存储从 137,538,168 降至 137,286,796 bytes，降幅很小，不能宣称已实现端到端稀疏存储。CPU 编译仍展开全部逻辑关系，参数变更后的边界归约仍扫描域；高密度候选或范围回退也仍可能达到 O(P)。进一步消除这些成本需要内部逻辑域与物化字段的延迟表示，同时保留现有逐行 patch、迁移和回读契约。
